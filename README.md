# Elite Carpentry & Renovations

Static marketing site for a carpentry and renovation contractor in Cornwall,
Ontario. Built to acquire quote inquiries and convey trust, optimised for local
search across Cornwall, Akwesasne and Stormont, Dundas & Glengarry.

No dependencies, no framework, no build server. Plain HTML/CSS/JS generated by
Python and served from GitHub Pages.

**Domain:** www.elite-carpentry.ca · **Stack:** GitHub Pages + Formspree

> **This repo is public** — GitHub Pages requires it for a custom domain on the
> free tier, so treat every file here as published. Launch checklist, client
> notes, commercial context and anything candid live in `NOTES.local.md`, which
> is gitignored. Keep it that way: if a note would be awkward for the client or
> a competitor to read, it does not belong in this file or in a code comment.

## Build

```bash
python3 tools/build.py
```

Generates all 18 pages plus `sitemap.xml`, `robots.txt` and `site.webmanifest`,
then rewrites root-absolute paths to depth-correct relative ones.

| Script | Purpose |
| --- | --- |
| `tools/build.py` | Builds the whole site. The only command you normally run. |
| `tools/brand.py` | **Single source of truth** for name, phone, email, hours, services, locations. |
| `tools/chrome.py` | The only copy of `<head>`, header, nav, footer and shared sections. |
| `tools/content_services.py` | Per-service copy, FAQs and the **stock** photo fallback. |
| `tools/content_locations.py` | Per-location copy and FAQs. |
| `tools/content_projects.py` | Captions, alt text and crop focus for the owner's real project photos. Carousel order. |
| `tools/project-photos.py` | Crops, resizes and WebP-encodes the real job photos from `photos/originals/`. Needs `pillow-heif` for iPhone masters. |
| `tools/brand-assets.py` | Publishes the supplied logo to web sizes (**resize only**) and copies the favicon set verbatim. |
| `tools/relativize.py` | Rewrites `/assets/…` → `../assets/…` by page depth, in `href`, `src` **and `srcset`**. Idempotent. |
| `tools/make-images.py` | Builds the 1200×630 social card around the supplied logo (needs Pillow). |
| `tools/fetch-photos.py` | Downloads, crops, compresses and WebP-encodes the stock photos. |
| `tools/check-links.py` | Verifies every internal link, `srcset` candidate and `#anchor` resolves. Non-zero exit on failure. |

Local preview:

```bash
python3 -m http.server 8770 --directory .
```

### Why everything is generated

topreno's maintenance hazard was header/footer markup copy-pasted into every
HTML file *and* duplicated again inside its page generator — change a nav link
and you have to find every copy. Here every page comes from `chrome.py`, so
there is exactly one copy. **Do not hand-edit the generated `.html` files**;
your changes will be overwritten on the next build. Edit the Python.

## Content and honesty rules

These are not style preferences. The site's entire job is conveying trust, and
each of these protects it.

- **Two photo sets, and the difference decides how they may be described.**
  - `assets/img/projects/` — the owner's **real work**. May be captioned as theirs. Copy lives in `tools/content_projects.py`; full-res masters in `assets/img/photos/originals/`.
  - `assets/img/photos/` — **licensed stock**. Descriptive alt text only, never attributive ("a wooden privacy fence with a lattice topper", never "a fence we built in Cornwall"), and **never captioned** — a caption under a photo reads as a claim about that photo. Credits: `assets/img/photos/CREDITS.md`.
- **Never invent job details.** The town, client, date, price and product brand were not supplied with the photos, so none appear in the captions — every line describes only what is visible in the frame. Ask the owner before adding any of it.
- **No unverified claims.** No review counts, no star ratings, no warranty term, until the owner confirms real numbers. Anything the owner has confirmed is recorded in `NOTES.local.md`.
- **No invented prices.** The cost FAQs explain what drives a price without quoting one.

### The quote form

Posts to the Formspree endpoint in `brand.FORM_ACTION`, delivering to
`brand.FORM_RECIPIENT`. It appears on **13 pages** — contact, all six services, all six locations — and
every copy is generated from `chrome.quote_section()`, so there is one form to
maintain, not thirteen.

Each copy carries a hidden `page` field naming its source (`Service: Decks`,
`Location: Cornwall`, …). That is the only way to tell which page earned a lead
once they are all landing in one inbox, and it is worth keeping.

**Verified by driving the real handler with `fetch` stubbed**, so nothing was
sent: it POSTs to the right endpoint with `Accept: application/json`, carries
all ten fields, shows the success state and clears the form on `ok`, shows the
error state and re-enables the button on failure, blocks submission when the
`_gotcha` honeypot is filled, and blocks submission when required fields are
empty.

**What that does NOT prove: that the endpoint delivers.** A GET or OPTIONS to
Formspree returns the same response for a real form ID and an invented one, so
the ID cannot be validated without an actual POST — and a POST sends a real
email. Before launch somebody must:

1. Submit the live form once, for real.
2. Confirm it arrives at the address in `brand.FORM_RECIPIENT` — **check the junk folder**.
3. Mark `formspree.io` a safe sender.

Do this even though the form says "Request sent". That message only means
Formspree returned HTTP 200; it says nothing about whether the mail was
delivered, and **a misconfigured endpoint fails silently and looks fine.**
Formspree's free tier also caps submissions per month — worth knowing what the
limit is before a busy spring.

### Stock is retreating, and that is the point

Nine real photos are live: the home page carousel, and the lead figure on
three of the six service pages. **Decks, bathrooms and kitchens run on the
owner's own work** — those three stock files were deleted, not left in the
folder. Only **fencing, siding and windows** are still on stock.

Retiring another one is a two-line job:

1. Drop the master in `assets/img/photos/originals/`, add an entry to `PROJECTS` in `tools/content_projects.py` with a **`service`** key naming the page.
2. Run `python3 tools/project-photos.py && python3 tools/build.py`, then delete the stock file and its rows in `tools/fetch-photos.py` and `CREDITS.md`.

`build.py` picks real work over stock automatically — `service_figure()` looks
up `REAL_FIGURES` first — so nothing else needs editing.

**Crops are checked by eye, never assumed.** Almost every master is a portrait
phone photo, so the 16:10 service-page cut discards more than half the frame.
Each entry carries a `focus` (vertical crop centre, 0 = top) and an optional
`focus_wide` for the 16:10 band. They were set by rendering a sweep and looking
at it — e.g. the bathroom sits at `0.24` because centring that frame put the
toilet dead centre. If you change a photo, re-check the crop.

**HEIC masters need `pillow-heif`** (`python3 -m pip install pillow-heif`).
Without it `project-photos.py` skips the iPhone files with a clear message
rather than failing the build.

**Held back on purpose.** Four masters in `originals/` are deliberately not
published, and `UNUSED` at the foot of `tools/content_projects.py` says why for
each — so nobody "helpfully" adds them back without knowing. One of them,
`deck1`, was the same frame as `deck-alum` at a third the resolution; publishing
both would have shown one job twice in one carousel.

### The owner in structured data

`/about/` carries a full `Person` node for **Jake Martin** (`#owner`) — name,
job title, photo and a paraphrase of the biography.

The owner is not staff, and the markup must not imply he is. schema.org has no
`Organization` → `Person` "owner" property — the vocabulary offers `founder`,
`employee` and `member` and nothing else — so three properties carry it
between them:

| Property | Where | Says |
| --- | --- | --- |
| `founder` | business → Jake | the company is his |
| `jobTitle: "Owner"` | on the Person | his role, in plain words |
| `worksFor` | Jake → business | affiliation, matching "he is on the tools" |

`worksFor` is affiliation, **not** employment status — it is what makes the
graph bidirectional so the two nodes resolve to one entity. **Do not "fix" it
to `employee`.**

**The full name appears in visible copy, not only in the markup.** Structured
data is meant to describe what a reader can actually see, so `/about/` says
"Elite Carpentry is Jake Martin's business" once and uses "Jake" from then on.
If that sentence is ever reworded, the surname has to survive somewhere visible
on the page or the `Person` node stops being backed by anything.

Pages other than `/about/` carry a name-only `founder` stub under the same
`@id`, so no page ships a bare reference to a Person it does not describe.

**Known, pre-dating this work:** the *business* node does not get the same
treatment. `/about/` and the six service pages reference `{"@id": ".../#business"}`
without defining it on the page — the service pages do it from `Service.provider`,
which is the link that ties a service to the company. The node is fully defined
on the home page and on every location page, and consumers that crawl the site
do merge by `@id`, but it is not guaranteed per-page. Fix would be the same
one used for the Person: emit a `@type` + `name` + `url` stub wherever the
business is referenced but not defined.

## SEO

- Unique `<title>` and meta description per page; absolute canonical, OG and Twitter tags.
- JSON-LD: `GeneralContractor` (home + per-location), `Service` (per service page), `FAQPage`, `BreadcrumbList`, `WebSite`, `ItemList`, `ContactPage`, `AboutPage`.
- **Every FAQ schema entry mirrors a visible `<details>` block**, generated from one list in `chrome.faq_section()`. Invisible FAQ markup risks a manual action — do not decouple them.
- No service × location cross-pages. 36 near-duplicate pages is a thin-content liability; the internal-linking mesh (every service page links all six locations, every location page links all six services, nav dropdowns link all twelve from every page) gets the coverage without it.
- `sitemap.xml` is generated with the build. Update `lastmod` in `build_meta_files()` when content changes materially.

## Design

Chrome, black and red, per the owner's brief.

- Chrome is a **gradient** (`--chrome-grad`), never flat grey — flat grey reads cheap. Used on rules, bevels, the logo and large numerals. **Never on body text.**
- Brand red `#E01B24` is only **4.08:1** on `--ink` — large text only. Red *text* therefore swaps per surface: `--red-ink` on light (5.4:1), `--red-lift` on dark (5.9:1). Full-strength red stays for fills and stripes, where the 3:1 UI threshold applies.
- **Any new dark section class must be added to the surface-role selector** in `style.css` (the `.dark, .steel, .hero, …` rule) or its text renders near-black on near-black.
- All text verified at WCAG AA (audited in-browser; 0 failures across 134 text nodes on the home page).
- `.reveal` starts at `opacity: 0` and is un-hidden by IntersectionObserver, with a `<noscript>` fallback so copy is readable if JS never runs.
- **The project carousel is progressive enhancement.** The viewport is a native CSS scroll-snap container, so every slide is reachable by scroll, swipe and keyboard with no JavaScript; `main.js` only adds the arrows and dots, and they stay `display: none` until it does. There is deliberately **no auto-advance** — it takes control away from the reader and is a well-known accessibility problem.
- Carousel position is derived from `scrollLeft`, not from an IntersectionObserver rooted on the viewport. That looks like the natural fit and is not: once the carousel scrolls out of the window its root rect is empty, so it stops reporting and the dots silently freeze.

### The logo

The designer's package lives in `assets/img/brand/elitelogo/` (SVG, EPS, PDF,
PNG, JPG and a `favicon_io` set). It is the source of truth.

**Every pixel on the site is the designer's.** The only operations performed on
the artwork are **resize** and **crop** — no redrawing, no recolouring, no
re-typesetting, no shadow work, no change to spacing inside any piece.
`tools/brand-assets.py` publishes it:

| Output | Used for |
| --- | --- |
| `brand/logo-1200.*` | Social card — stacked, whole |
| `brand/logo-480.*` | Footer, painted at 200px — stacked, whole |
| `brand/mark-192.*` | Header, painted at 64px — house + EC |
| `brand/word-144.*` | Header, painted at 46px — ELITE + rule + sub-line |
| `favicon.ico`, `favicon-*.png`, `apple-touch-icon.png`, `android-chrome-*.png` | Copied **verbatim** from `favicon_io/` — not re-rendered |

The transparent master is `PNG/Artboard 1 copy.png`. (`PNG/Artboard 1.png` is
the same artwork fully opaque, on white — do not use it on the site.)

No page sets the company name in type beside the logo: the artwork already
contains it, so that would print the name twice. The accessible name comes from
the link's `aria-label` and the `img` alt is empty, so a screen reader does not
hear the brand twice either.

#### Two lockups, one file

- **Stacked** — the artwork whole, clear space intact. Footer, social card, and every print/signage use.
- **Horizontal** — the mark and the wordmark cropped apart and set side by side. **Header only. Approved by the owner 2026-08-16.**

The horizontal lockup exists for one reason. "CARPENTRY & RENOVATIONS" is a
single line of capitals, and capitals stop reading below roughly **8px**.
Squeezed into a nav bar, the stacked lockup put that line at **5.3px** on
desktop and 4.6px on mobile — a grey smudge. Side by side, the wordmark gets the
width it needs and the line clears **8.5px**. Making the header taller does not
fix it: the stacked lockup would have to be 140px tall, i.e. a 150px bar.

This is why `.logo .word` is set taller than its stacked proportion against the
mark would give it. **Shrink it and the sub-line goes back to being texture.**

`brand-assets.py` re-derives the crop boxes' validity on every run: each box
must still be the alpha bounding box of its band, and the mark/word split must
still fall inside the shadow-only rows between them (peak alpha 58, against
168+ where real artwork starts). If the logo is re-exported at different
proportions **the build stops** rather than shipping a mis-cut logo.

**Anything beyond these two crops is a change to the logo and needs the owner's
sign-off. Do not alter it without asking.**

## Forms

One Formspree endpoint, set in `tools/brand.py`. Every form carries a hidden
`page` field ("Service: Decks", "Location: Cornwall", "Contact page") so leads
are attributable to the page that produced them.

- Honeypot `_gotcha` — submissions with it filled are dropped silently.
- If the endpoint still holds `YOUR_FORM_ID`, the handler **shows the error state rather than silently swallowing a lead**.
- Formspree free tier is 50 submissions/month.
- **Formspree requires you to confirm the first submission from a new domain before it will deliver.** Send one real test after the DNS cutover.

## Deploy

Branch-based GitHub Pages, same as `topreno`. No Actions workflow.

```bash
git init && git add -A && git commit -m "Initial site"
gh repo create jchad086/elite-carpentry --public --source=. --push
gh api -X POST repos/jchad086/elite-carpentry/pages -f source[branch]=main -f source[path]=/
```

Verify everything on the project URL (`jchad086.github.io/elite-carpentry/`)
**before** attaching the domain — relative paths are what make that work, and
attaching the domain makes GitHub 301 the project URL, killing the preview.

DNS, then attach the domain **last**:

| Type | Name | Value |
| --- | --- | --- |
| CNAME | `www` | `jchad086.github.io` |
| A | `@` | `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` |

```bash
gh api -X PUT repos/jchad086/elite-carpentry/pages -f cname=www.elite-carpentry.ca
```

> **Certificate lesson, learned the hard way on topreno:** Pages bundles apex +
> www into one certificate at *provisioning* time only. **Both DNS records must
> exist before the domain is attached**, or the cert covers just the one name
> and Pages will not re-provision — waiting, re-PUTting and detach/reattach are
> all no-ops while a valid cert exists. Enable `https_enforced` only once the
> cert is issued; Pages refuses it while provisioning.
